# ONB-04 CSV operator contract

Status and actual evidence are in [PHASE_TRACKER.md](./PHASE_TRACKER.md); design decisions are in [D11](./DECISIONS.md#onb-d11--onb-04-canonical-imports-credentials-and-recovery--implemented-design). Open **People → Bulk setup (CSV)** or the optional People step in the guided workspace. VSSYL Console uses its normal **Open facility** work session and the same workspace. Customer User and PlatformStaff identities remain distinct.

Use the dataset's downloadable, header-only UTF-8 CSV template. CSV works for every dataset advertised in this workspace. Facility structure CSV remains in the canonical Facility Builder; ordinary employee patches remain in **Update existing employees** under D05. The separately authorized [ONB-06 combined workbook](./ONB_06_WORKBOOK_CONTRACT.md) uses these same planners and receipts; individual CSV remains available.

| Dataset | Required new intent | References / preservation |

Existing: exact `employeeId` or unique email; confirm account match in preview. | Real email; explicit active platform role and work arrangement. Optional phone, Team ID, Job Role ID, Job Title ID. Existing rows are assertions/reuse, never patches. Historical/unlinked/revoked identities need People/lifecycle review. |

Use exact existing hierarchy names. Current Asset Builder authority is required. Creates registry identity/status history only. Reuse changes no fields or assignment. |

`rowRef` is an optional unique file-local reference, not a persistent identifier. Department references accept an exact authorized installation ID, normalized Product/installation key (HFN/DIETARY lineage), or exact unique name. They cannot purchase, license, install, enable or publish Products. Canonical reference IDs are listed on the page. Never invent IDs or duplicate people/places per Department.

Blank/omitted fields preserve existing data. These additive modes reject clears, credential/lifecycle columns, unknown/duplicate headers, malformed rows, formulas and duplicate targets. Use ONB-01 for approved field clears/patches and existing lifecycle/authority actions for changes. Source row numbers retain physical CSV line provenance, including quoted multiline cells. Maximum source: 2,000,000 UTF-8 bytes; workforce 500 rows, other datasets 2,000; cells 2,000 characters. Plain text codes retain leading zeros. Templates contain no sample people.

1. Prepare licensed installations separately, then canonical Facility structure. Share Department locations, create/reuse workforce, add memberships, then register Assets. Configuration and publication remain with existing Builders.
2. Upload and preview. Preview performs no domain, batch, audit or invitation mutations. Inspect each create/add/reuse/blocked row and the resolved canonical IDs. Explicitly check each existing global-account match; identical names are not linking authority.
3. Confirm the reviewed file within 30 minutes. Authorization, source, targets and dependencies are checked again under transaction protection. Changed source/scope/actor/authority/material facts require fresh preview. Each request attempts at most 25 rows independently.
4. Read actual durable row receipts: committed, reused, blocked, failed, or unknown/unattempted. Earlier commits survive other failures. Exported receipt CSV is escaped for spreadsheet-active text and contains no passwords, PINs or credential hashes.
5. If interrupted, recover the saved batch and reconcile before retrying. Actor/Facility/dataset-scoped browser hints hold only batch/review tokens; authority and receipts live on the server. An active request must finish or its bounded lease expire. Continue remaining reviewed rows while the review remains valid; otherwise re-preview remaining intent. Canonical reuse and receipts prevent duplicate replay. There is no file-wide rollback.
6. Account activation is a separate explicit task after employment commits. Send/retry activation and inspect delivery and acceptance state. Unconfigured mail, delivery failure and superseded links do not undo employment. Existing passwords are preserved. Eligible PIN enrollment remains pending until a customer GM/FA uses the existing People PIN action. No credential is generated/exported, and normal authentication/activation deadlines still apply.

Console workforce and relationships use real PlatformStaff-attributed receipts. Existing Asset management restrictions remain: Facility Administrator status alone, including Console's work-session role shape, grants no Asset management without its canonical Department context. A blocked Asset row must be handled by an already-authorized operator in Asset Builder; this importer never impersonates one.

The source file is not uploaded to support storage or retained as raw bytes. The private database retains bounded normalized reviewed intent and immutable attempts for reconciliation. Source custody and approval are different concerns. Keep `AUTH_SECRET` consistent across application instances; changing it invalidates outstanding reviews, while existing receipts remain subject to current read authorization.

Before release, track ONB-02/03/04 migrations in the normal reviewed change set and rerun migration integrity. This contract does not authorize paid implementation, customer-data backfill, deployment or renaming.

ONB-06 adds exact scoped canonical IDs as Asset floor/neighborhood/space references, with ID priority over human names. Human-readable matching remains supported. Workbook file-local references resolve to those IDs through committed receipts; ordinary CSV does not gain a second executor. Facility structure CSV retains its canonical Builder owner. All five ONB-02–05 migration tracking/integrity and production scanner prerequisites remain binding before release.

### ONB-07 confirmed rollback recovery

D17 adds bounded retries only for a positively rolled-back Prisma P2034 transaction. Each attempt reauthorizes and revalidates the same reviewed intent under existing locks; delivery remains outside the transaction. Unknown COMMIT/network outcomes still reconcile durable receipts before retry. Exhausted contention and other failures remain visible actual outcomes; no file-wide rollback is promised. Individual CSV datasets and update-only ONB-01 semantics are unchanged.
