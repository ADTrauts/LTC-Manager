# Dietary Asset Issue Reporting Guide

**Phase:** 10A — Dietary Asset Operations  
**Audience:** Frontline STAFF / LEAD (including Quick PIN) and Supervisors  
**Flag:** `DIETARY_ASSET_OPERATIONS_ENABLED=true`

## When to report

Report when equipment is damaged, not working correctly, unsafe to use as-is, or needs attention — even if a workaround exists.

## Where to report

- Unit Workspace — Asset status panel / Report Issue  
- Asset profile (when you have access)  
- From a related Evidence Record when appropriate  

## What to include

- **Which Asset**  
- **Short summary** and description of what you observed  
- **When** you observed it  
- **Operational impact** (neutral language):  
  - No immediate service impact  
  - Workaround available  
  - Service at risk  
  - Equipment unavailable  
- Whether the equipment **remains usable** (not a technical safety certification)  
- Optional workaround instruction  
- Optional related Evidence Record  
- Optional comment  

## Duplicate reports

If a clearly open Issue already exists for the same Asset problem, the system points you to it instead of creating a duplicate. You can still file a **distinct** new problem.

## After you report

- Your report is saved as an **Asset Issue** (not a Work Order).  
- Online: synchronized immediately.  
- Offline (when supported): **Saved on This Tablet** until reconnect; then synchronizes exactly once. Refresh preserves the pending report. Changing user or Unit does not retarget a pending report.  
- Do not assume Supervisors see a purely local pending report until it synchronizes.

## What you will not see

Vendor costs, internal management notes, other Employees’ full reports, Work Order administration, or full Asset history.

## What you cannot do

Asset Builder, Vendor management, Work Order management, or declaring technical safety certification.
