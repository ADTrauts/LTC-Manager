# Offline Runtime — Operator Recovery Note

When shared tablets lose connectivity during meal service, use this guide. No secrets or credentials are required.

## Commands remain pending

1. Confirm the tablet shows **Saved on this tablet** or a pending count on the Unit Workspace.
2. Restore Wi‑Fi and wait for **Synchronizing** → **Synchronized**.
3. If stuck on **Unable to Sync**, tap **Retry synchronization**.
4. Do not power-wash the tablet while pending commands exist unless IT has exported recovery status.

## Reauthentication required

1. Session may have expired or been revoked while offline.
2. Sign in again with the normal facility login or Quick PIN flow.
3. Reopen the same Unit Workspace online to refresh the offline bundle.
4. Pending commands remain attributed to the original user; they synchronize only when authority still matches.

## Device was rebound

1. Admin rebind changes which unit the tablet serves.
2. Commands for the previous unit stay tied to that unit — they are not retargeted.
3. Open the new unit online to issue a fresh bundle for the new binding.

## Conflict review required

1. A supervisor or manager opens the Unit Workspace conflict panel.
2. Choose **Mark duplicate**, **Reject with reason**, or **Apply as correction** (correction requires reason and preserves both histories).
3. Contact dietary leadership if the authoritative server time disagrees with kitchen records.

## Tablet must be replaced

1. Ensure pending work on the old tablet has synchronized or been reviewed.
2. Bind the replacement tablet to the facility (and unit if applicable).
3. Have staff open the Unit Workspace online once before relying on offline mode.

## When no offline bundle exists

The tablet must reconnect and load the Unit Workspace online at least once while authenticated. Offline mode cannot invent authority without a prior approved bundle.
