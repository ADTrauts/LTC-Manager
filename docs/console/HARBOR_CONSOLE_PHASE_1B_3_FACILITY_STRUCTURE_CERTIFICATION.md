# Harbor Console Phase 1B.3 Facility structure certification

This change implements the approved synthetic Facility structure contract. Hosted assistance and grant issuance are disabled in code. Local testing requires an explicit opt-in, a loopback HTTP host and disposable loopback database, and server-side Facility and staff allowlists. The Preview branch of the gate additionally matches the Vercel Preview deployment hostname against an approved list. A future activation must verify Vercel Authentication for that deployment before changing the hard disable.

The only assistance read is `GET /console/assistance?context=<opaque reference>`. The reference is tied to one signed Harbor login and leaves Facility, Unit, and Space IDs on the server. The view is a dynamic HTML document with no client scripts, export or customer links. It rejects speculative and RSC requests, sends private no-store headers, and is excluded from the service worker. Authorized requests read canonical `Facility`, `Unit` and `UnitSpace` scalars directly inside the Harbor authority transaction. The existing Builder loader is outside the read path. Invalid, inactive, unplaced and excluded branches never reach the view. The response is refused above 250 Units or 1,000 Spaces.

The two separate, same-origin governance POST handlers are for synthetic authorization setup, session lifecycle and consent. They do not offer customer structure mutations. An allowlisted OWNER can approve a different viewer only after the current Facility Administrator records structured consent. The policy separates revoke and audit capabilities. Current Administrator withdrawal records the actual User and ends the grant and open sessions. Staff audit events record the actual staff identity. Approval and consent are single-use with an idempotent exact approval retry. The grant lasts at most 24 hours, and a session lasts at most 30 minutes, bounded by grant and login expiry. Switching requires the prior opaque reference and atomically closes that context. The old reference fails even in a second tab. SQL holds at most one open session per signed login.

An authorized statement uses the Phase 1B.2 staff → grant → session lock order, checks scope and consent, reads the tree without customer writes, writes a redacted Harbor audit event, and checks expiry before releasing the result. A rollback or audit failure returns no tree. Redacted denial records omit submitted scope. Review and pruning are separate internal operations restricted to the approved security reviewer list. Redacted synthetic events have a 90-day policy. The receipt table is physically independent and omitted from that pruning.

## Migration and rollback

`20261116220000_harbor_structure_pilot` is forward only. It adds consent, grant/session metadata, the one-open-session index, and protected logout receipts. New receipts carry the verified token expiration plus the configured verifier tolerance (zero). Historic Phase 1B.2 receipts lacked the exact expiry. The migration copies them with a conservative bound of logout timestamp plus the old 12-hour signed TTL. Keep the prior audit metadata readable. The migration refuses overlapping historical open sessions for the same login so an operator can review the evidence before retrying. No data backfill runs on a Facility, Unit, Space or Room Type.

The disabled deployment works on the prior schema with ordinary, unbound Harbor logins. Before an approved pilot, use only the authorized staged Preview and synthetic database, confirm the prior migration ledger and recovery copy, then apply the pending migration with separate approval. Preserve evidence and receipts on rollback. Close the pilot and drain every bound login through signed expiry before reverting to any build that does not write the independent receipt, including reachable older aliases. Keep the Phase 1B.1 retirement as the lowest rollback revision. Do not down-migrate this data.

## Evidence

The two-Facility SQL run verifies exact output shape and omitted branches, scoped grant and consent, independent approver/revoker/reviewer authority, failed audit write, concurrent switch, revocation ahead of a waiting read, logout replay, and lifecycle expiry. Database triggers refuse customer DML on fixture Facility, Unit, Space, Room Type and responsibility rows. Snapshots match before and after, and the deliberately unlinked room stays unlinked. Audit pruning and staff deletion cannot remove a live logout receipt. The short signed token test verifies the exact expiration cutoff. The bounded reader and hosted disable checks also run hermetically.

The migration was exercised on an empty disposable PostgreSQL database and a populated copy of the prior schema. The latter verified that a copied historic receipt survives deletion of its original staff audit row and showed no Prisma schema drift. The draft PR records browser and hosted evidence against its reviewed commit.
